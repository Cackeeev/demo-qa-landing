# CLASSIC / MUSIC

Первый рабочий прототип личного музыкального плеера для iPhone в духе iPod Classic: металлический корпус, экран с синим выделением и настоящее интерактивное колесо управления.

## Проверить на iPhone через GitHub Pages

Адрес публикации: **https://cackeeev.github.io/demo-qa-landing/**.

В версии GitHub Pages работают интерфейс, колесо, демозаписи и импорт своей музыки. Откройте в Safari и при желании добавьте на главный экран. Авторизация VK ID на статическом хостинге не выполняется: для неё нужна полная версия с Node-сервером. В интерфейсе Pages вместо неработающего входа показано объяснение.

Готовая статическая сборка находится в `docs/`. Для обновления выполните `npm ci`, `npm run build:pages`, `npm run test:pages`, затем закоммитьте исходники и `docs/` и отправьте их в `main`. В настройках репозитория **Settings → Pages** выберите **Deploy from a branch**, ветку **main**, папку **/docs**, затем **Save**. Если Pages ещё не включён, сайт станет доступен после его включения и завершения сборки GitHub.

## Что работает

### Эксперимент: интерфейс поверх веб-версии VK без сервера

Установочный файл: **https://cackeeev.github.io/demo-qa-landing/userscripts/classic-vk.user.js**. Исходник находится в `public/userscripts/classic-vk.user.js` и автоматически включается в обе сборки. Отдельная PWA на GitHub Pages не получает музыкальный поток: userscript управляет существующей страницей VK в Safari.

1. Установите [Userscripts для Safari](https://apps.apple.com/app/userscripts/id1463298887), включите расширение и при необходимости выберите локальную папку для скриптов.
2. Откройте установочный файл в Safari, откройте меню Userscripts и подтвердите установку. Разрешите расширению доступ к установочной странице и VK.
3. Войдите на настоящем сайте VK, откройте «Музыка → Мои треки». На iPhone при необходимости запросите настольную версию сайта.
4. Откройте плавающую кнопку CLASSIC. Скрипт распознаёт загруженные строки записей и нажимает исходные кнопки VK. Для входа или подтверждений есть «Показать VK». Новые плейлисты и дополнительные записи сначала открываются на самой странице VK, затем список обновляется в CLASSIC.

В этой реализации нет извлечения cookies/токенов, запросов к неофициальному музыкальному API, передачи библиотеки или звука через сторонний сервер, внешних JS-зависимостей и загрузки исполняемого кода. Оригинальная страница и её плеер сохраняются. Диагностика содержит только версию, домен, количество найденных строк и признаки обнаруженных контролов — без имён треков, ID аккаунта или данных сеанса.

**Ограничения теста:** адаптер проверяется на изолированной странице, воспроизводящей характерную DOM-разметку VK, с реальным WAV-аудио. Доступ к настоящему аккаунту не проверен. Текущая версия VK может иметь другую разметку; тогда скрипт явно покажет, что записи не распознаны. Перемотка доступна только при обнаруженном HTML audio/доступном ползунке. Фоновое воспроизведение и iPhone Safari требуют проверки на устройстве. Переключатель «Скрывать рекламные блоки» выполняет только косметическое скрытие известных блоков; **аудиореклама не блокируется**. Запуск пользователя не имитируется, успешный вход и воспроизведение не подделываются.

Проверка адаптера: `npm run prepare:media && npm run test:userscript`. Тесты перехватывают фиктивную страницу VK и аудиофайл; реальный аккаунт, пароль и токены не используются. Не присылайте их в чат.

### Основной плеер

- Медиатека, поиск, альбомы, исполнители и подборки.
- Встроенная «Инструкция» в главном меню и экране подключения: настройка VK ID, свои файлы и установка на iPhone. Для чтения не нужно выходить в README.
- Анимации нажатий и переходов с учётом «Уменьшения движения». В инструкции можно включить короткий виброотклик, если браузер поддерживает Vibration API; по умолчанию он выключен. Safari на iPhone этот API не поддерживает, поэтому там доступен визуальный отклик.
- Колесо: вращение пальцем/мышью, центральная кнопка выбора, MENU, предыдущий/следующий трек и play/pause. На компьютере также работают ↑ ↓, Enter, Escape и пробел.
- Настоящее воспроизведение трёх собственных синтезированных демозаписей по 32 секунды, перемотка, повтор и случайный порядок.
- Импорт аудиофайлов с устройства. Файлы не загружаются на сервер и доступны в текущей вкладке до обновления страницы. До 60 файлов за сеанс; поддержка кодеков зависит от браузера (для iPhone предпочтительны MP3, AAC/M4A и WAV).
- Серверный поток авторизации VK ID: OAuth Authorization Code + PKCE S256, одноразовый `state`, проверка адреса возврата, получение профиля, HttpOnly cookie, выход и попытка отзыва токена. Пароль вводится только на сайте VK; токены не передаются фронтенду и не сохраняются в localStorage.
- Манифест PWA, иконка для главного экрана и service worker для оболочки. Ответы `/api/`, `/auth/` и адреса с параметрами авторизации не кешируются. Это не офлайн-загрузчик музыки.

## Что ещё не подключено

**Вход через VK ID и доступ к музыке VK — разные возможности.** Основной PWA-плеер не получает библиотеку или потоки VK. Экспериментальный userscript показывает загруженные записи и управляет исходным плеером непосредственно на странице VK; его ещё нужно проверить с настоящим аккаунтом. Полноценный AdBlock не реализован. Успешный вход через VK ID сам по себе не предоставляет музыкальный API. У пользователя пока нет зарегистрированного приложения VK ID, поэтому этот отдельный поток входа с реальным аккаунтом также не проверен.

Серверный обмен с VK проверяется автоматическими тестами с подставными ответами провайдера; это не доказательство успешной реальной авторизации. Нельзя заменять его локальным «успешным входом» или запрашивать у пользователя пароль/токен в чате.

## Запуск

Нужен Node.js **24.5 или новее** (проверено на Node 24.19). Сервер и клиент работают с одного адреса, порт 3000 по умолчанию.

```sh
npm ci
npm run prepare:media
npm run dev
```

Откройте `http://localhost:3000` на своей машине. Для проверки плеера вход не требуется: выберите «Мои треки», затем запись, либо «Добавить файлы». Без зарегистрированного приложения окно входа покажет, какие настройки нужны.

Продакшен-сборка:

```sh
npm run build
npm start
```

`npm run build` проверяет TypeScript, генерирует аудиодемо и PNG-иконки, затем собирает клиент в `dist/`. `npm start` запускает Node-сервер, который отдаёт сборку и обрабатывает авторизацию. Одна только публикация статических файлов на GitHub Pages для этого проекта недостаточна.

## Подключение настоящей авторизации VK ID

1. Создайте **веб-приложение** в [кабинете VK ID](https://id.vk.ru/about/business/). Публичный ID приложения отличается от ID личной страницы VK. Настройки и доступность приложения определяются VK.
2. Разместите Node-сервер на доступном **HTTPS-адресе**. В кабинете VK ID зарегистрируйте домен и точный адрес возврата: `https://ваш-домен/auth/vk/callback`. Для iPhone `localhost` означает сам телефон, а не компьютер или облачную машину.
3. Скопируйте `.env.example` в `.env` и укажите:

   ```dotenv
   VK_CLIENT_ID=публичный_числовой_ID_приложения
   PUBLIC_ORIGIN=https://ваш-домен
   PORT=3000
   ```

   В `PUBLIC_ORIGIN` не должно быть пути или завершающего `/`. Сервер разрешает HTTP только для loopback-разработки. Допускается ввести публичный ID в самом окне подключения; для этого всё равно нужен зарегистрированный адрес возврата. Поддержка localhost-адреса в кабинете VK требует отдельной проверки; основной сценарий входа — HTTPS.

4. Перезапустите сервер, откройте «Подключение → Войти через VK ID» и пройдите вход на странице VK. После возврата интерфейс должен показать ваше имя. Доступ к музыке при этом останется отдельным неподключённым источником.

Секретный ключ приложения для этого публичного PKCE-потока не используется. Не вводите в прототип пароль VK, готовые токены, cookies других клиентов или данные чужих приложений.

Сервер обращается к `id.vk.ru` по HTTPS; этот домен должен быть разрешён в сетевых настройках облачной среды. В текущей облачной машине проверка подключения встретила отказ сетевого прокси `403`, поэтому реальный обмен токеном не проверен. Нужный домен добавлен в черновик настройки среды; сохранение черновика само по себе не меняет работающую сетевую политику. При переносе в другой хостинг проверьте его сеть отдельно.

Сеансы хранятся **в памяти одного Node-процесса** и завершаются при перезапуске. Для многопользовательского постоянного сервиса потребуется общее хранилище сеансов. Токены никогда не журналируются. Не включайте логирование тел OAuth-запросов в reverse proxy.

Реализация сверена с открытым исходным кодом официального [VK ID Web SDK](https://github.com/VKCOM/vkid-web-sdk), включая `device_id`, PKCE и проверку `state` при обмене кодом. Это не сторонний неофициальный музыкальный API.

## Установка на iPhone

После размещения на HTTPS откройте плеер в Safari → «Поделиться» → «На экран Домой». Управление Media Session подключено, но фоновое воспроизведение и кнопки экрана блокировки требуют проверки на настоящем iPhone; проверка размеров экрана в Chromium не заменяет Safari/iOS. Системная громкость регулируется кнопками телефона.

## Проверки

```sh
npm test
npm run build
npm run test:e2e
```

Серверные тесты проверяют PKCE, одноразовый state, CSRF, срок действия попытки входа, ошибки VK, смену сеанса после входа и выход. Браузерные тесты запускают **продакшен-сборку**, реально воспроизводят аудио, импортируют WAV, проверяют управление, мобильные размеры, перенаправление на VK и кеш PWA. Внешняя страница VK в браузерном тесте перехватывается; действующие учётные данные не нужны.

Для браузерных тестов нужен Chromium: используется `CHROMIUM_PATH`, установленный `/usr/bin/chromium` либо браузер Playwright (`npx playwright install chromium`). Сначала выполните `npm run build`. Не запускайте тесты параллельно с чужим приложением на порту 3000.

Демозаписи создаются скриптом `scripts/generate-media.mjs` из математического синтеза, без сторонних фонограмм. Сгенерированные WAV/PNG, `node_modules/`, `.env` и `dist/` не входят в Git. Исходный старый лендинг удалён; история Git сохранена.
